# 大肥鱼 P1 + P2 实施目标与验收门禁

## 授权范围（2026-11-05）

在现有 **Telegram 单 Owner + AstrBot v4.29.4 + ChatGPT SIWC + 单容器** 上新增四项能力。保持原 QQ/NapCat 完全隔离、继续复用 Docker Volume `dafeiyu_telegram_data` 和现有 `notes.json`。

1. **P1 提醒与待办**：在 Telegram 创建、列出、完成、取消待办；支持明确时间的一次性提醒、重启恢复和状态可查。
2. **P1 自动长期记忆**：对完成的普通聊天保守提取低敏感偏好/长期目标，逐条有原文证据；用户能禁用、查看、删除。
3. **P2 只读公开信息检索**：可搜索网页、读取公开 HTTPS 页面并根据来源摘要回答，禁止对内网、凭据网页、非 HTTPS、脚本和任意操作的访问。
4. **P2 有依据的主动关怀**：仅根据用户实际待办、临近提醒、近期互动判断是否发送，尊重开关、频率与繁忙状态。

## 可观察成功标准

- Owner 发送 `/todo 买书`，能够通过 `/todos` 看见、`/done ID` 完成；重启后保留状态。
- Owner 发送 `/remind 明天上午9点提醒我开会`，有准确的时区/时间确认，到点仅一次尝试投递，重复或网络不确定状态可查询并手动 `/retry ID`；缺少时间时拒绝猜测。
- 普通聊天中明确表达持久偏好/目标后，自动记忆能在保守规则下存入、/memories 查看、/forget 删除；过敏、身份/地址、凭据和商业机密不能通过自动记忆写入。
- `/search` 返回真实搜索来源；`/read` 只读公开 HTTPS 页面；`/research` 使用检索摘要生成带来源的解释。公网失败时明确失败，不编造。
- `/nudge now` 基于真实待办产生可追溯内容，近期刚聊过/无依据时跳过；`/nudge off` 停止主动关怀。每天最多一次自动关怀。
- 受影响路径静态检查、集中测试及用户侧 Telegram 实测通过后，才进入 PR/CI/Merge；部署另行批准。

## Non-goals

- 不新增微服务、VectorDB、MCP 工具循环、浏览器自动化、网站登录、付费搜索 API、Cron 外部守护服务。
- 不在自动记忆中保存密码、个人健康或敏感身份信息；不默认抓取用户邮箱、日历或其他应用数据。
- 不进行未经确认的购物、付款、发送邮件、修改网站或手机操作。
- 不改变已存在的 SIWC Token 和 Telegram Bot 凭据及其存储路径。
- 不迁移旧 QQ 数据、不修改原作者仓库、不顺带重构无关项目代码。

## 已知取舍

- 搜索使用第三方公共检索引擎，搜索词会提交给相应服务；高敏感查询不要发送。
- `/read` 是**只读 HTTPS 正文提取**，不是真实交互式浏览器；JS 重站、登录墙和 PDF 不支持。
- 提醒投递遵循 **at-most-once 自动尝试**：Telegram 网络在发送后超时可能产生 `unknown`，只有用户确认后才手动重试，不谎称已发送。
- 自动记忆按规则保守提取；并非全量对话记忆，也不保证识别所有值得保留的信息，用户可随时关闭和手动管理。
- 新能力继续在既有 Docker Volume 下使用小型独立 SQLite 表，不动 AstrBot 核心表；恢复先保留旧笔记和会话历史。

## 当前执行门禁

- **Phase D**：在 `feat/dafeiyu-p1-p2` 完成四项代码、静态检查、若安全则分批 Commit/Push；**不运行单测、不创建 PR、不触发 CI、不 Merge、不部署**。
- **Phase V**：只有开发完成并取得用户验收授权后才运行受影响路径测试并修复。
- **Phase R**：验收通过且获发布批准后 PR → CI → Merge。生产 Mac 容器切换属于独立操作。

权威流程：`AGENTS.md` 和 `docs/DEV-WORKFLOW-v1.0.md`。
